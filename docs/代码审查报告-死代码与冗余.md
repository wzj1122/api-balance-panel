## D. 顺带发现：审查中撞见的真实 Bug（建议尽快修）

1. **概览页「删除账号」失效（断链）**：`preload/index.ts` L55 调用 `ipcRenderer.invoke(IPC.ACCOUNT_REMOVE, { id })`（包成对象），而 `src/main/ipc.ts` L102 处理时 `const id = String(payload ?? '')` → 得到 `"[object Object]"` → `store.removeAccount` 永远返回 false → 删除失败，界面弹「删除失败：主进程返回删除失败」。对比 `IPC.KEY_SECRET` 的处理（L290 兼容两种传参），ACCOUNT_REMOVE 两侧约定不一致。建议主进程改为 `asRecord(payload).id` 或 preload 改回传原始字符串。
   - 注：Key 管理页的删除走 `KEY_BULK`（ids 数组），不受影响。
2. **重启后账号「分类标签」与「回收站」状态丢失**：`store.ts normalizeAccount()`（L144~183）加载 config 时**没有拷贝 `tags` 与 `deleted_at`** 字段 → 每次启动软删除的账号复活成普通禁用账号、标签全部清空。与 `keys.ts` L9 注释「标签与回收站字段存在 config.json 的账号上」矛盾（落盘了但加载时被丢弃）。
3. **余额耗尽档位恒为「正常」**：`AccountCard.vue` L56 `pctLevel(ratio)` 传入的是 0~1 的比率，而 `pctLevel` 内部按 0~100 的百分比判断（`>=90` 红 / `>=70` 黄）→ 永远返回 `'ok'`，卡片的 warning/danger 档位从不触发。应传 `pctLevel(ratio * 100)` 或改判断口径。
4. **接口监控「历史展开时点检查会收起」**：`MonitorPanel.vue` L196 `if (historyFor.value) await openHistory(...)` 与 `openHistory` 的 toggle 语义（L231-234）冲突，已展开历史时点「检查」会把面板收起而不是刷新。
