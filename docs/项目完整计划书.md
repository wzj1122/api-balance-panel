## 1. 项目概述

**一句话**：一个 Windows 桌面应用，把多个 AI 平台和中转站的余额/额度集中到一个窗口里看，自动定时刷新、低余额弹通知；对没有公开接口的平台（如小米 MiMo），内置浏览器登录一次后自动抓 Cookie、自动更新余额。

**要解决的核心痛点**（来自用户原话）：

| 痛点 | 本应用的解法 |
|---|---|
| 每个平台要单独登录网页看余额，来回切换烦 | 一个窗口看全部，自动定时刷新 |
| 小米 MiMo 这类平台「老要手动看」 | 内置浏览器首次登录一次，之后自动刷 Cookie 抓余额 |
| 中转站、官方、自定义平台接口五花八门 | 统一适配器 + 万能自定义适配器（抓包即用） |
| 想知道一共还值多少钱 | 实时汇率折算成人民币「合计约 ¥xxx」 |
| 余额低时怕错过 | 低余额系统通知 + 卡片标红 |

**面向用户**：不懂技术的个人开发者（界面文案全部大白话，密钥只存本机）。

## 4. 程序总体架构

采用 electron-vite 的标准三段式 + 一条铁律：

```
┌─────────────────────────────────────────────────────────┐
│  渲染进程 (src/renderer)  Vue 3 界面                      │
│  - 只通过 window.api 白名单调主进程                        │
│  - 拿不到密钥明文，拿不到 Node 模块，不直接发 HTTP          │
└──────────────────────────┬──────────────────────────────┘
                           │ contextBridge (preload 白名单)
┌──────────────────────────▼──────────────────────────────┐
│  预加载 (src/preload)  薄封装，只暴露方法                   │
└──────────────────────────┬──────────────────────────────┘
                           │ ipcRenderer.invoke / on
┌──────────────────────────▼──────────────────────────────┐
│  主进程 (src/main)                                        │
│  - 适配器（联网查余额，唯一的联网出口）                      │
│  - 数据层（配置 / 加密 / 快照）                             │
│  - 调度器（定时刷新）/ 并发池 / 缓存 / 通知 / 托盘 / 汇率     │
└─────────────────────────────────────────────────────────┘
       共享类型/常量/格式化 (src/shared) —— 两端共用，不得 import node/electron
```

**铁律（安全）**：
1. 所有联网请求只在主进程发起；渲染进程永不直接发 HTTP。
2. 密钥明文只存在于主进程内存；跨 IPC 的类型 `AccountView` 在类型层面就删掉了 `secret_enc`。
3. `nodeIntegration: false` + `contextIsolation: true`，渲染进程没有 Node 权限。

## 7. 平台适配器详解

**适配器模式**：`Adapter = (account, ctx) => Promise<BalanceResult>`，`ctx.getSecret(account)` 在主进程内解密取明文密钥。新增平台 = 加一个文件 + 在 `PROVIDERS` 注册一行，界面无需改代码。

| 平台 | 接口 | 认证 | 关键取值 | 单位 |
|---|---|---|---|---|
| **DeepSeek 官方** | `GET https://api.deepseek.com/user/balance` | Bearer Key | `balance_infos.0.total_balance / granted_balance / topped_up_balance / currency` | CNY（接口给） |
| **硅基流动** | `GET {base}/v1/user/info` | Bearer Key | `data.balance / totalBalance / chargeBalance` | CNY |
| **New API 中转站** | `GET {base}/api/user/self` | Bearer Key + 可选 `New-API-User` | `data.quota / used_quota`，×`1/quota_per_usd` | USD |
| **小米 MiMo** | `GET /api/v1/balance` + `/api/v1/tokenPlan/usage` | Cookie | `data.balance / cashBalance / giftBalance`；plan 用量 ×0.000001 | CNY / M Credits |
| **万能自定义** | 自填 URL/Header/Body | 自填 | 点号路径提取（`dig`） | 自填 |

**关键实现细节**：
- **点号路径取值 `dig`**：`a.b.0.c` 支持 dict + 数组下标，取不到返回 undefined（与 Python 原型一致）。
- **数值 `num(v, scale)`**：自动转 number，失败返回 null；`scale` 用于单位换算（如 M Credits ×0.000001）。
- **DeepSeek**：不返回总额，`total` 用账号手填的 `quota_total`；`note` 显示账户可用性。
- **New API**：站点点数 `quota` ÷ `quota_per_usd` 折算成美元；`total = remaining + used`。
- **MiMo**：现金余额接口**必须成功**，401/403 抛 `COOKIE_EXPIRED`（提示重新登录）；Token Plan 接口**尽力而为**，失败不拖累现金展示。
- **自定义**：三个关键字段全取不到时抛 `BAD_PATH`；自动补 `Accept: application/json`。

## 8. 数据层

### 8.1 配置读写（store.ts）

- **文件**：`config.json`（结构 `version / crypto / settings / accounts / notice_state`）。
- **可靠性三件套**：
  1. **原子写**：写 `.tmp` 并 fsync → rename 覆盖，断电不写坏。
  2. **单份备份**：覆盖前把旧文件复制为 `.bak`。
  3. **损坏恢复**：读失败 → 回滚 `.bak`（状态 `recovered`）→ 仍失败则用默认（`reset`）；坏文件重命名 `config.corrupt-<ts>.json` 不删除。
- **归一化**：逐字段兜底，缺字段补默认、越界拉回范围，保证界面拿到的永远是合法对象（不白屏）。

### 8.2 密钥加密（crypto.ts）

- **首选**：Electron `safeStorage`（Windows 走 DPAPI，系统级加密）。
- **降级**：不可用时用「本机弱混淆」（XOR + 本机盐 = 主机名+用户名），界面弹黄色横幅提示。
- **方案版本化**：`crypto.scheme / version` 写进 config，未来换方案旧配置仍可读；解密失败不抛异常，返回空串。

### 8.3 余额快照（snapshot.ts）

- 每次查询（含失败）追加一条，异步落盘（1 秒节流）。
- **防膨胀**：保留天数裁剪 + 单账号最多 2000 条。
- 提供 `listByAccount(accountId)`（趋势图用）、`count()`、`removeByAccount()`。

## 10. 查询引擎

- **缓存**：`Map<accountId, {row, at}>`，命中时长由 `cache_seconds`（默认 60s）决定；`force=true` 跳过缓存。
- **并发池**：`runPool(tasks, concurrency)` 纯函数，最多 `concurrency`（默认 8）个任务同时跑，单个失败不影响其它。
- **逐条推送**：每完成一条立刻 `balance:row`，全量完成 `balance:updated` + 写快照 + 判断通知。
- **调度器**：`setInterval`，窗口隐藏（最小化）暂停、回到前台立即补刷；改刷新间隔 `reset()` 热重启。
- **低余额通知**：`remaining < threshold` 时弹系统通知；每账号每日限 `notice_max_per_day` 次（跨日自动归零）。

## 11. 安全设计

| 项 | 措施 |
|---|---|
| 进程隔离 | `nodeIntegration:false` + `contextIsolation:true` |
| 网络出口 | 只在主进程发请求，渲染进程无 fetch/Node 权限 |
| 密钥存储 | safeStorage（DPAPI）加密，明文不落盘 |

| 请求预检 | URL/Header 非 ASCII 拦截（防中文粘错导致崩溃） |
| 隐私 | 汇率请求只发货币代码 USD/CNY，不带任何账号信息 |
| 单实例 | `requestSingleInstanceLock`，二开聚焦已有窗口 |

## 12. 二期已完成能力详解

### 12.1 MiMo 浏览器自动化（第 1 步）

- **机制**：`loginToSite()` 用 `BrowserWindow` + `session.fromPartition('persist:login-<host>')`（站点专属 session）。
- **流程**：点「登录 MiMo」→ 弹登录窗口 → 用户手动登录 → 关闭窗口 → 自动读该站点 Cookie 拼成字符串 → 加密存进账号 `secret`。
- **不存密码**：只存 Cookie；约 24 小时过期，适配器检测到 401/403 抛 `COOKIE_EXPIRED`，卡片标红提示重登。
- **零体积代价**：复用 Electron 自带 Chromium，不引入 Playwright。

### 12.2 安装包 + 托盘 + 自启（第 2 步）

- **安装包**：electron-builder NSIS，`oneClick:false`、可选安装目录、桌面/开始菜单快捷方式。
- **托盘**：点 × 不退出 → `win.hide()` 缩到托盘；托盘菜单「显示主面板 / 退出」；左键单击显示窗口。
- **开机自启**：`app.setLoginItemSettings`；**开发模式跳过**（否则会注册 electron.exe）；设置项开关变更时热同步。

### 12.3 成本折算 + 趋势图（第 3 步）

- **汇率**：`fx.ts` 请求 `open.er-api.com/v6/latest/USD`（无 key），取 `rates.CNY`；1 小时缓存 + 在途去重；失败走上次缓存，再无则内置兜底 7.2；**绝不抛错**。
- **成本折算**：`SummaryBar` 里「成本折算」chip，公式 = 人民币账号合计 + USD 账号合计 × 汇率；仅当存在 USD 账号时显示，小字标注实时/缓存/兜底。
- **趋势图**：`TrendChart.vue` 纯 SVG 手绘折线图（无图表库），点卡片「趋势」图标懒拉快照渲染。

## 13. 错误码与文案总表

适配器只抛错误码，人话文案统一在 `errors.ts` 产出（改文案只改一处）。

| 错误码 | 界面文案 |
|---|---|
| HTTP_401 / 403 | 密钥错了或过期了，去平台后台重新生成一个 |
| HTTP_404 | 网址填错了，检查中转站地址（只填域名，不要带 /v1） |
| HTTP_429 | 查太频繁了，平台限流了，把自动刷新间隔调大一点 |
| HTTP_5XX | 平台自己挂了，等一会儿再试 |
| TIMEOUT | 连不上平台，检查网络或代理 |
| NETWORK | 网络不通，检查代理或防火墙 |
| CERT | 网络不通，检查代理或防火墙（证书校验失败） |
| BAD_URL | 网址里有中文或特殊字符，检查一下是不是粘错了 |
| BAD_HEADER | 请求头里有中文或特殊字符，多半是把说明文字当成密钥粘进去了 |
| BAD_JSON | 平台返回的不是数据（可能是登录页），多半是 Cookie 过期了 |
| BAD_PATH | 没在数据里找到余额字段，检查一下"取值路径"填对没 |
| MISSING_FIELD | 还有必填项没填：X |
| COOKIE_EXPIRED | 登录已过期，点「登录」重新获取一次 Cookie |
| UNKNOWN_TYPE | 未知的平台类型，请重新选择平台 |
| UNKNOWN | 查询失败（下方小字显示原始信息，方便排查） |
