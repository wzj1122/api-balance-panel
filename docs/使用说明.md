# API 余额面板 · 使用说明

> 一个本地余额监控小工具：把 DeepSeek、硅基流动、小米 MiMo、New API 中转站、阿里云百炼等账号加进来，
> 自动定时刷新余额头像卡片，余额低于阈值时变色提醒。所有密钥只保存在你自己的电脑上（本机加密），不会上传任何地方。

---

## 一、安装与运行（拿到安装包怎么用）

1. 从发布页下载 **「API 余额面板」安装包**（约 130 MB）。
2. 双击运行 → 跟着安装向导走（默认装到当前用户目录，可点「高级选项」改安装位置），装完后桌面和开始菜单会出现 **「API 余额面板」**。
3. 首次启动时 Windows 可能弹出蓝色提示「Windows 已保护你的电脑」（未知发布者）：点 **「更多信息 → 仍要运行」** 即可。这是因为安装包没有购买代码签名证书（发布者为个人、非商业签名），属正常现象，不是病毒。
4. 所有账号配置保存在系统的用户数据目录（Windows：`%APPDATA%\API 余额面板`，即安装后程序名对应的目录），换电脑/清数据前想备份，把整个文件夹拷走即可（里面是加密的密钥，拷给别人也没事，但建议别乱发）。
5. 尝鲜体验不需要装也可以看仓库里自带的系统截图，或使用程序内的「演示模式」。

> 免安装分发：把构建产物里的 `win-unpacked` 目录整体分发（`API 余额面板.exe` 必须连同同级 `resources` 文件夹一起），即为绿色版。

## 二、添加账号：各平台分步说明

点击界面右上角「添加账号」，先选平台类型，再按下面的步骤填。

### 1) DeepSeek 官方

1. 打开 [DeepSeek 开放平台](https://platform.deepseek.com/) ，登录后在左侧「API Keys」创建一个 Key（以 `sk-` 开头）。
2. 面板里选「DeepSeek 官方」，把 Key 粘贴进「API Key」栏，保存即可。
3. 可选：「总额」填了你充值过的总额，卡片上才能算百分比，不填也能用。

### 2) 硅基流动

1. 打开 [硅基流动控制台](https://cloud.siliconflow.cn/) 登录（没账号先注册）。
2. 面板里选「硅基流动」，点「登录获取 Cookie」——会弹出登录窗口，登录完成后窗口会自动关闭，程序自动抓取 Cookie。
3. Cookie 失效后卡片会提示「重新登录」，点卡片上的编辑 → 再点一次登录按钮即可。
4. 说明：官方已于 2026-08-14 下线 API Key 余额接口，所以这个平台必须用「登录」方式。

### 3) 小米 MiMo

1. 打开 [MiMo 开发平台](https://platform.xiaomimimo.com/) 登录。
2. 面板里选「小米 MiMo」，点「登录 MiMo 获取 Cookie」，会直接跳到小米账号登录页，登录完成窗口自动关闭。
3. Cookie 约 24 小时过期，过期后点「重新登录」即可。

### 4) New API / One API 中转站

1. 你的中转站后台（如 `https://你的域名`）生成一个令牌（一般 `sk-` 开头）。
2. 面板里选「New API / One API 中转站」，填站点地址（**只填域名，不要带 /v1**）和令牌。
3. 如有用户 ID 需求（部分站点），一并填写；没有就留空。

### 5) 自定义（抓包填写）

适合会抓包的开发者：填写请求地址、请求头，以及余额字段的取值路径（JSON 路径），支持倍率换算。

### 6) 阿里云百炼 ⭐（重点，步骤较多）

阿里云余额在「费用与成本」控制台（账号级），要给它授权一台只读的访问密钥（AccessKey），步骤如下：

**第 1 步：创建 RAM 用户（或直接用主账号，推荐新建一个）**

- 打开 [RAM 控制台 - 用户](https://ram.console.aliyun.com/users)，点「创建用户」。
- 登录名随便取（如 `panel-read`），访问方式勾选「OpenAPI 调用访问」。
- 官方教程（可对照）：[创建 RAM 用户并授权](https://help.aliyun.com/zh/ram/product-overview/create-and-authorize-a-ram-user)

**第 2 步：给该用户授权 AliyunBSSReadOnlyAccess（关键！）**

- 在 [用户列表](https://ram.console.aliyun.com/users) 找到刚创建的用户，点「新增授权」（或点进用户 → 权限管理 → 新增授权）。
- 搜索框输入 `AliyunBSSReadOnlyAccess`，勾选它（系统策略，只读费用查询，**只读不会动到账务**），确定即可。
- 官方教程（可对照）：[为 RAM 用户授权](https://help.aliyun.com/zh/ram/user-guide/grant-permissions-to-the-ram-user)

**第 3 步：创建 AccessKey**

- 在 [用户列表](https://ram.console.aliyun.com/users) 点进该用户 → 「AccessKey 页签」→「创建 AccessKey」，按提示完成验证。
- **立刻把「AccessKey ID」和「AccessKey Secret」都下载/复制下来**（Secret 只在创建时显示一次，之后再也看不到，丢了只能重新创建）。
- 官方教程（可对照）：[创建并使用 AccessKey](https://help.aliyun.com/zh/ram/product-overview/quick-start-create-and-use-accesskey-pairs-for-programmatic-calls)

**第 4 步：填进面板**

- 面板里选「阿里云百炼」，把 AccessKey ID 填第一栏、AccessKey Secret 填第二栏，保存。
- 新建的密钥要等 **2~3 分钟**才全局生效，刚创建完立刻刷新若报错，等一会儿再刷。

**阿里云常见报错对照**（卡片失败态下方的小字会显示原文/详情）：

| 详情里的关键字 | 含义 | 怎么办 |
|---|---|---|
| InvalidAccessKeyId / SignatureDoesNotMatch | ID 或 Secret 填错了（或刚建还没生效） | 检查是否复制完整、两栏是否填反；等待 2~3 分钟再刷新 |
| Forbidden / NoPermission / AccessDenied | 密钥没有费用查询权限 | 回到第 2 步，给该用户授权 AliyunBSSReadOnlyAccess |
| 网络不通 | 机器解析不了阿里云接口域名 | 检查网络/代理/DNS，稍后重试 |

**关于「API Key」**：百炼控制台里「API-KEY 管理」的 `sk-` 开头密钥是**调用模型**用的令牌，
阿里云没有给它开放余额查询接口，所以**不能用它查余额**；查余额只能用上面这种 RAM AccessKey。

**代金券读不到时怎么排查**：卡片下方的小字会直接写明原因——「代金券读取失败：<原因>」或「代金券接口返回 N 张但无可用券（状态：…）」。
程序日志（侧边栏「运行日志」搜 `aliyun`）里还会记录：接口返回几张券、可用几张、剩余合计多少；把日志级别切到 **debug** 还能看到每张券的状态/面值/余额/到期时间。
常见情况：

| 现象 | 可能原因 | 怎么办 |
|---|---|---|
| 备注写「代金券读取失败：AccessKey 权限不足…」 | RAM 用户缺费用查询权限 | 按第 2 步授权 `AliyunBSSReadOnlyAccess` |
| 备注写「N 张但无可用券（状态：…）」 | 券已过期/已用完，或阿里云改了状态字面量 | 看状态值判断；若是字面量变化，把日志发给开发者 |
| 控制台能看到券、面板金额却不含券 | 券的 `AvailableTime` 未到生效时间，或券属于其他账号 | 到「费用与成本 → 卡券」确认券的生效时间与归属账号 |
| 卡片金额比控制台少一大截 | 券没算进来（面板口径 = 资金账户 + 可用代金券） | 同上，看备注里的小字提示 |

### 7) 商汤 日日新（SenseNova）⭐

商汤的额度是「Token Plan 双积分池」，与常见的钱包余额不同：

1. 打开 [SenseNova 平台](https://platform.sensenova.cn/console) 并登录（支持商汤账号 / 手机号等方式）。
2. 面板里选「商汤 日日新（SenseNova）」，点「登录并获取」——弹出登录窗口，登录完成后自动关闭，程序抓取登录态。
3. 卡片会显示三行口径（有专属池时）：
   - **5 小时窗口剩余**（主数值 / 进度条）：当前 5 小时窗口内还能用多少积分，窗口到期自动重置；
   - **周额度剩余（7 天）**：本周总共还能用多少积分，每周重置；
   - **Flash-Lite 积分池**：Flash-Lite 系列模型的专属池（与通用池分开计量）。
4. 说明与注意事项：
   - 额度接口**只认登录态（Bearer token），不认 API Key**，所以必须用「登录」方式。
   - **登录态的真实寿命 ≈ 3 小时（平台硬限制）**：商汤的服务端会话 Cookie（`oauth2_authentication_session`）
     到期时间 = 登录时刻 + 3 小时，**而且不会因为访问而顺延**（实测反复加载控制台也不延长，到期时间纹丝不动）；
     控制台也没有任何"刷新会话"的接口（没有 refresh token）。所以：
     - 会话**还活着**时，面板的静默续期可以一直用它换新 token（这就是"不用反复登录"的原理）；
     - 会话**一旦到期**，只能重新登录——平台侧无法绕过。
   - **到期前 15 分钟会弹通知提醒**你重登（面板每 5 分钟检查一次），不再"用着用着突然失效"；
     重登只需在账号编辑里点一下 **「只重新登录」**（登录完自动保存并关窗）。
   - **别手动清程序数据目录里的 `Partitions/`**：静默续期靠的就是里面的会话 Cookie。
   - **窗口关闭不等于成功**：关窗前程序会把凭据存进账号并真跑一次额度查询，查得通才算成功；查不通会明确写出原因且不自动关窗。
   - 「公测 FREE」套餐各模型单独计量积分，面板展示的是**当前账号的积分池额度**，不是按模型拆分。
   - 积分不等于人民币：如需换算成本，可在账号里填「单位」（默认「积分」）；「设置 → 成本折算」可设积分与元的折算率。

## 三、日常使用

- **自动刷新**：默认每 60 秒刷新一次（可在设置里调整 15 秒~24 小时）。程序最小化到托盘时继续刷新。
- **低余额提醒**：每个账号可单独设置「剩余低于 X 时提醒」；触发后卡片余额变黄/显示「低余额」标记，并弹系统通知。
- **单账号刷新**：点卡片右上角箭头图标；失败卡片上有点击重试按钮。
- **趋势图**：点卡片右上角趋势按钮可看余额走势（保存在本机）。

## 四、常见问题

1. **提示「网络不通」**：本机解析不了平台接口域名。换网络/关代理再试；阿里云已内置选择可解析的接入点。
2. **提示「密钥错了或过期了」**：DeepSeek/New API 检查 Key 是否有效；阿里云看上方对照表；MiMo/硅基流动点「重新登录」。
3. **提示「网址填错了」**：New API 站点地址只填域名，不要带 `/v1`；检查是否有特殊字符。
4. **余额显示为 0 / 字段找不到**：多为平台返回结构变化，把小字详情发给开发者排查。
5. **换电脑怎么带配置**：拷贝 `%APPDATA%\API 余额面板` 整个文件夹过去即可（密钥是本机加密的）。

## 五、隐私说明

- 所有密钥 / Cookie 只保存在本机，使用系统级加密（Windows DPAPI）落盘，不会上传、不会进入任何日志。
- 程序只在每次刷新时请求各平台官方余额接口，无其他外联。
- 建议给阿里云等平台单独创建「只读」专用密钥，见上文授权步骤。

### 3b) 小米 MiMo 套餐（Token Plan）

- 「小米 MiMo」管**余额**（现金/赠送），「小米 MiMo 套餐」管**套餐用量**（用量/总额度/套餐名/有效期），两者**共用同一个登录状态**。
- 选「小米 MiMo 套餐」→ 点「登录 MiMo 获取 Cookie」会直接跳到小米账号登录页，登录完成窗口自动关闭；若你已添加过「小米 MiMo」，添加时勾选「同时添加另一个方式」可以一键把套餐卡片也加上。
- 卡片显示：套餐名（如 Lite）、已用 / 总额度（M Credits）、剩余量、有效期至 X 月 X 日。

## 六、界面与新功能

### 1) 侧边栏导航

左侧边栏是全部功能的入口（点一下即可切换整页视图）：
- **概览**：账号卡片面板（按类型分组，组头可点击折叠）。
- **每日使用状况**：按日统计消耗 + 余额耗尽预估 + 导出报表。
- **平台用量**：按平台（类型）汇总的消耗统计。
- **运行日志**：全部运行记录（已脱敏，可导出）。
- **主题外观**：主题、背景图与玻璃效果。
- **设置**：刷新 / 提醒 / 主题 / 数据 / 关于。
- **使用说明**：本说明的整页版（不再弹窗，直接铺满内容区）。

### 2) 每日使用状况统计

- 数据来自程序每次刷新自动记录的历史快照，无需额外开启；没数据时页面会提示。
- 口径：**套餐型账号**（如小米 MiMo 套餐）直接用「已用」增量；**余额型账号**按「剩余变化」估算（中途充值会掩盖消耗，仅供参考）。
- **停机期间消耗**：如果中间彻底退出过软件（关窗缩到托盘不算），重新打开后这段余额下降无法精确按天归属，会单独列在表格的「停机期间」列、并在日历对应日子打上 **⏸** 标记。它**已计入「合计（含停机）」**（= 逐日之和 + 停机期间，也就是这段时间实际掉了多少），但**不计入每日均值、耗尽预估和预算判断**（避免把多天消耗堆到重新打开的那一天把日均拉高）。判定口径：与上一条快照的间隔超过 **2 小时**（且不小于刷新间隔 × 3）才算停机——跨零点那种几十分钟的空档不会再被误判。
- **近 7 天**：消耗信息卡 + 按单位柱状图 + 账号×日期明细表。
- **近 30 天**：日历形态——按自然月展示，格子颜色越深当天消耗越多（按主单位归一化）；每月顶部显示**每月消耗合计、消耗最多的日期、消耗最多的账号**；点击任意有数据的天，弹窗显示当天每个账号的用量明细和单位合计。

### 2b) 数据校正（历史数据不对时用）

若某个账号某天的数据明显异常（例如网络抖动导致那次刷新读到了错的余额），到侧边栏「**数据校正**」页修：

1. **改某天用量**：选账号 → 在日期列表里找到那天 → 填「改成」的实际值 → 保存。不受近 7/30 天窗口限制。
2. **回退到某次状态**：在「回退」区选一条历史快照（或直接填一个准确余额）→ 确认后，**该时刻起整体平移**：余额回到当时的值，之后每天的消耗照常准确（平移不改变相邻快照的差值）。
3. **撤销**：每条校正都能单条撤销，也能「全部还原」；原始快照从不被修改，校正记录单独存在数据目录的 `corrections.json`。

说明：校正在数据读取的统一出口生效，所以**每日使用、平台用量、使用报告、日历、趋势图、耗尽预估、预算判断会一起跟着变**（日均与耗尽预估按校正后的数据重算）；卡片实时数字也会套用校正，并显示「已手动校正 ±X」标记。

### 3) 使用报告（按单位分别统计）

- 报告里**每个单位各算一套**（合计、环比、平台构成、最多账号、时段分布、疑似充值）：不同单位（如 CNY 与积分）不能相加，所以分开列。
- 顶部会列出**所有单位的数字**；点某个单位的标签，下方明细就切到那个单位（以前只显示数值最大的那个单位，导致另一种单位的账号在报告里完全看不到）。
- 与「每日使用状况」**同一套口径**：跨期（停机）与「读取闪断」都不会被算成某一日的消耗，两个页面的数字一致。
- 若某天数据明显异常（例如网络抖动读到错值），到侧边栏「**数据校正**」页修：可「只改这天」（只影响那一天）或「忽略这天」（整段剔除，该天显示为空）。

### 4) 余额耗尽预估

- 按近 7 天日均消耗外推剩余可用天数；只有 ≥2 天有效数据才会推算。
- 概览页卡片上会显示「预计 MM-DD 耗尽 · 约剩 N 天」（<3 天红、<7 天黄）；每日使用状况页也会列出每个账号的预计耗尽日期。

### 5) 导出 CSV

- 每日使用状况页右上角「导出 CSV」：账号 × 日期全量明细 + 按单位合计，含 BOM，Excel 直接打开不乱码。

### 5) 平台用量统计

- 按平台类型 × 单位聚合（对应「每日使用状况」的账号级口径），支持近 7 / 30 天切换。
- 顶部信息卡：总消耗（分单位）、**积分折合人民币（估算，只在有积分型平台时显示）**、消耗最多平台、今日消耗。
- **「折合人民币」只对积分型单位折算**（目前是商汤这类按「积分」记账的平台）：
  - 元 / 美元单位（DeepSeek 官方、硅基流动、MiniMax、智谱、阿里云…）本身就是金额，**直接看数字即可**，所以它们的「折合人民币」列**留空**；
  - 积分和元数量级差很多（100 万积分 vs 几块钱），直接并排比会得出错误印象，所以积分型平台按「设置 → 成本折算」的折算率换成人民币参与对比条定宽；
  - 默认折算率 **111111**（1 元 ≈ 11.11 万积分，即 **100 万积分 ≈ 9 元**），按 DeepSeek flash 高峰价反推：输入缓存命中 0.04 / 未命中 2 / 输出 8 元每百万 Token；
  - 折算值只是**估算基线**，不是平台官方汇率、也不代表真实扣费；可在「设置 → 成本折算」改成你自己的口径，填 0 = 不折算；
  - 以后新增积分型平台会自动走同一套逻辑，界面不用改。
- 平台消耗对比条形图 + 平台×日期明细表（含今日、7日均、合计、折合人民币），支持导出 CSV。

### 5.1) 表格里的数字（每日使用状况）

表格里**没有任何颜色强调**，都是普通字色，含义写在各列的悬浮提示里：

- **「停机期间」列**：软件没运行的那段时间里余额掉了多少。这段时间跨了多天、无法精确按天归属，所以**单独列一列**，并已计入「合计（含停机）」，但**不计入**日均、耗尽预估与预算判断。
- **「充值」**（该格写的是「充值」两字）：当天余额反而增加了（疑似充值），充值会掩盖消耗，所以那天的消耗算不出来，这一格不代表用量。
- **「预计耗尽」**：按近 7 天日均外推的剩余可用天数，仅供参考。
- 鼠标停在单元格上会写明具体原因与数值（例如「消耗 X · 停机期间另有 Y，已计入合计」），不用靠颜色记忆。

### 5.2) 设置里的「成本折算」

- 「设置 → 成本折算 → 积分折算率」：填「多少积分算 1 元」，右侧会实时显示 `1 元 ≈ X 积分（100 万积分 ≈ Y 元）`，点「恢复默认」回到 111111。
- 这个数**只影响展示**（平台用量页的估算列、对比条排序），不会改动快照与任何统计结果。

### 6) 浅色主题

- 设置 → 显示 → 主题，点一下立即生效并保存（不用再点「保存设置」）。
- 深色 / 浅色就是「主题外观」页里的**经典深色 / 经典浅色**，两边是同一个设置，会实时同步；跟随系统则按 Windows 的深浅色在这两套之间自动切换（系统换色时界面实时跟着变）。

## 七、监控与玩法（新功能）

### 1) 接口监控（自己填 Key + 地址的正式监控）

- 在「Key 管理」页顶部切换到「接口监控」标签页，点「添加监控目标」：填写**调用地址**、**API Key**，选择 POST（LLM 对话接口）或 GET（只读接口），可自定义请求头与请求体。
- 面板会**按你设定的间隔真实调用该接口**，记录每次的成功/失败、HTTP 状态码与响应耗时，并统计**可用率、平均/P95 延迟、连续失败次数**，以及近 30 天的每日可用率状态条；每个目标都能查看完整检查记录。
- 填完可以先点「试跑一次」验证配置（会真实调用一次，不保存、不计入统计），确认没问题再保存。
- **费用提示**：真实调用 LLM 接口会产生极少量费用，默认 POST 请求体已把 `max_tokens` 设为 1；也可以用 GET 模式指向平台的只读接口（如 `/models`）做到 0 费用。检查间隔最短 1 分钟，建议按需要设为 5~30 分钟。
- API Key 与账号密钥使用同一套本机加密（safeStorage），界面上只显示 `sk-****1234` 形式的掩码，明文不落盘。
- 目标可以单独「暂停/启用」，暂停后不再检查但历史保留；窗口最小化/隐藏时**仍会继续检查**，保证监控数据连续。

- 请求头与请求体里可以用 `{{key}}` 占位符，会替换成你填的 API Key（例如 `x-api-key: {{key}}`）；默认会自动带上 `Authorization: Bearer <key>`，如果你已经自定义了 Authorization / x-api-key 则不会重复添加。
### 2) 每日预算与告警

- 「设置 → 每日预算与告警」里按单位设置每天最多花多少（例如 CNY 每天 50）。概览页会出现预算进度条：今日已用、剩余额度、以及「按这个节奏余额还能用约 N 天」。
- 达到预算 80% 和 100% 时各提醒一次。
- 另外两类告警：**余额骤降**（单次刷新内跌幅超过设定百分比，默认 30%）与**接口异常**（连续查询失败达到设定次数，默认 3 次）。
- 「每日使用状况」会给每个账号一个**建议阈值**（近 7 天日均 × 3，约 3 天用量），可以据此调整账号的低余额阈值。

### 3) 使用报告与分享卡片

- **使用报告**页支持日报 / 周报 / 月报：总消耗、环比上期、活跃天数、日均、平台消耗构成、24 小时时段分布、疑似充值记录，以及一段「这段时间的你」趣味总结。
- 「生成分享卡片」会把报告画成一张 900×1200 的图片（PNG）保存到下载目录，可以直接发群里。
- 卡片上「总额 / 单位 / 其它单位 / 较上期」各占一行（多单位时不会叠字），数据格与「消耗构成」会跟着行数自动下移。
- 说明：报告**只基于金额消耗**——各平台接口不提供按模型 / Token 的调用明细，所以没有「最爱的模型」「消耗了多少 Token」这类数据；时段分布由快照采样推断，刷新间隔越短越准（5 分钟刷新可定位到小时级）。

### 4) 新手引导与演示模式

- 首次启动（还没有账号时）会弹出三步引导，可以「添加第一个账号」或「先看演示模式」。
- **演示模式**内置 6 个示例账号与最近 30 天的示例数据，能完整体验卡片、日历、统计、报告、接口监控等全部功能；数据只存在内存里，**不会写入你的配置、不发起任何请求**，点「退出演示」即恢复。
- 各个新功能标题旁的「?」是即时说明，鼠标悬停即可看到这个功能是怎么算的。

### 5) 托盘与通知

- 托盘图标悬停会显示「最低余额账号」或「几个账号查询失败」；右键菜单直接列出各账号余额，并提供**立即刷新 / 暂停自动刷新 / 显示主面板 / 退出**。
- 系统通知共四类：低余额、余额骤降、接口连续失败、每日预算超支。

### 6) 备份与恢复

- 「设置 → 数据 → 备份与恢复」可以一键导出全部配置与历史（JSON，密钥仍是本机加密后的密文），换电脑时导入即可恢复账号与设置。
- 注意：密钥密文与原电脑的系统账号绑定，导入后可能需要重新填写密钥；导入前会自动把原配置另存为 `config.json.pre-import.bak`。

### 7) 主题与背景

- 「主题外观」页提供 **12 套设计师主题**（深空蓝 / 亚克力 / 柔雾紫 / 编辑部等宽 / 科幻立体 / 蓝粉糖果，每套含深浅两版）+ 深色/浅色/跟随系统；可自定义背景图（支持蒙版与模糊）、开启**液态玻璃**效果。
- 与「设置 → 显示 → 主题」联动：选深色/浅色即切到对应经典主题，选跟随系统则按系统深浅色自动在经典深色/经典浅色之间切换；切换主题时，对应主题的内置背景会自动跟着换上。

### 8) 登录有效期与「续期登录」（商汤 / 小米 MiMo）

登录型平台的登录态都是「短期 token + 会话 Cookie」结构，token 只活几小时，所以面板做了三层处理，尽量让你不用反复登录：

1. **登录窗口优先复用既有会话**：再次登录时不会先清空凭据，而是先拿上次的会话试一次——平台认这个会话就会自动换新凭据，窗口自动关闭，**你不用输密码**；只有会话真的失效了才会清空并让你正常登录。
2. **后台保活**：面板在后台（含最小化到托盘）也每 20 分钟检查一次，凭据快过期时自动静默续期；查询前发现凭据临期也会先续期。**只要面板开着，登录态就会一直顺延**（商汤的会话 Cookie 与小米的 `passToken` 实测都是滑动续期的）。
3. **卡片上的「续期登录」按钮**：任何时候点一下就能手动续期；万一会话已彻底失效，会自动帮你打开登录窗口，登录完成后凭据与续期材料一起写回。

补充说明：

- 商汤的 `access_token` 是 **3 小时**的 JWT，没有 refresh token，续期靠会话 Cookie 换新；小米的 `passToken` 约 30 天，且每次使用会顺延。
- 面板不会去「搬运」你浏览器里的登录态（实测跨进程复制登录 Cookie 会失效），续期只使用面板自己那份持久化会话——等价于"浏览器一直开着"这个正常场景。
- 如果长时间（如数天）不开面板、或平台侧主动失效了会话，仍需要重新登录一次；此时点卡片「续期登录」会直接弹出登录窗口，一步到位。

### 9) 开机自启
- 「设置 → 系统 → 开机自启」点一下立即写入系统启动项（当前用户，无需管理员权限），开关下方会显示**真实状态**：已写入 / 未写入 / 被「任务管理器 → 启动」禁用 / 开发模式跳过。
- 开机自启启动时**不弹出主窗口**，直接常驻托盘在后台刷新，点托盘图标或桌面快捷方式即可打开主面板。
- 如果状态显示「被任务管理器禁用」，到「任务管理器 → 启动应用」里把「API 余额面板」启用即可（程序也会自动清理这条禁用记录）。
