| 项目信息 | 内容 |
|---|---|
| 文档语言 | 中文 |
| 目标用户 | 个人开发者（非技术背景也能看懂本文档） |
| 技术栈 | Electron + Vue 3 + Vite（electron-vite 脚手架），Node 侧主进程 + 渲染进程 |
| 项目名称 | `api_balance_panel` |

> **原始需求（一句话）**：一个人同时在用好几家 AI 平台和中转站，每家都要登录后台才能看到还剩多少钱。他想要一个**常驻电脑上的小窗口**，打开就能在一屏里看完所有账号的余额，不用再一个个登后台。

## 一、先说人话：几个词是什么意思

| 词 | 一句话解释 |
|---|---|
| **适配器** | 每家平台专门写的一段"取数小脚本"。告诉程序去哪个网址、带什么密码、从返回内容里哪个位置拿数字。加一个新平台 = 加一个适配器。 |
| **API Key / 令牌** | 平台给你的一串密码（一般 `sk-` 开头）。程序带着它去问平台"我还剩多少钱"。**等同于银行卡密码，不能给别人。** |
| **中转站** | 别人搭的中间商网站（New API / One API 这类），你在它那充值，它再转卖给各个 AI 平台。同一个软件可能搭了好几个，所以要支持多个。 |
| **Cookie** | 浏览器登录后网站发给你的一张"临时门票"。有些平台没有开放查询接口，只能靠这张门票去它网页后台偷看余额。**一般 24 小时就过期。** |
| **字段路径** | 接口返回一大串数据，余额藏在里面。用 `data.balance`、`data.list.0.remain` 这种"点号地址"告诉程序去哪一层拿数字。 |
| **倍率（scale）** | 有的平台返回"分"不是"元"，返回的是"百万分之一美元"。乘一个倍率换算成人能看懂的数字。差 100 倍填 `0.01`，差 100 万倍填 `0.000001`。 |
| **快照** | 每一次查余额的结果留一份存档。有了存档才能画"余额变化曲线"。 |
| **safeStorage** | Electron 自带的一个保险箱，把密钥加密后存在本机。别人直接打开配置文件也看不到明文。 |
| **系统托盘** | 屏幕右下角（时钟旁边）的小图标区。窗口关掉后程序缩到那里继续在后台跑。 |

## 二、产品定义

### 2.1 产品目标（3 个，互相不重叠）

1. **一屏看完全部余额**：一个窗口里展示所有已配置账号的剩余 / 总额 / 已用 / 单位 / 最后更新时间，不再逐个登录后台。
2. **配得上、看得懂**：非技术用户能通过界面表单完成账号增删改，失败时给出人话提示（"密钥错了或过期了"），而不是一串英文报错。
3. **密钥不出本机**：所有查询都由本机电直接发给平台官方地址，密钥用系统级加密存本地文件，程序不做任何中转或上报。

### 2.2 用户故事

| # | 用户故事 |
|---|---|
| 1 | 作为一个同时用 DeepSeek、硅基流动和 3 个中转站的人，我想打开一个窗口就看到所有账号还剩多少钱，这样就不用记 5 个网址、登 5 次后台。 |
| 2 | 作为一个怕忘记充值的开发者，我想每隔几分钟自动刷新一次余额，这样某个号快用光时我能第一时间发现，而不是调用失败才发现。 |
| 3 | 作为一个不太懂技术的用户，我想在界面上填个名字、选个平台、粘一下密钥就能加号，这样就不用去改看不懂的配置文件。 |
| 4 | 作为一个担心密钥泄露的人，我想密钥在本机加密保存、界面上只显示 `sk-****1234`，这样我截图分享面板时不会把密码漏出去。 |
| 5 | 作为一个用着小众平台的人，我想自己在浏览器 F12 里抓一次包、把网址和字段路径填进去就能用，这样不用等开发者给我适配新平台。 |

### 2.3 一期范围（已拍板，不推翻）

**一期只做"有公开余额接口"的平台：**

| 平台 | 类型标识 | 查询方式 | 来源 |
|---|---|---|---|
| DeepSeek | `deepseek` | `GET https://api.deepseek.com/user/balance`，Header `Authorization: Bearer sk-xxx`。返回 `balance_infos[0]` 里的 `total_balance` / `granted_balance` / `topped_up_balance` / `currency` | 原型 server.py + 方案文档 |
| 硅基流动 SiliconFlow | `siliconflow` | `GET {base_url}/v1/user/info`，Bearer 密钥。取 `data.balance` / `data.totalBalance` / `data.chargeBalance` | 原型 server.py |
| New API / One API 中转站 | `newapi` | `GET {base_url}/api/user/self`，Bearer 令牌；**部分站点需额外 Header `New-API-User: {user_id}`**。取 `data.quota`（剩余）与 `data.used_quota`（已用），单位是站点内部点数 | 方案文档 2.4 + 原型 server.py |
| 自定义（万能适配器） | `custom` | 用户自填 URL + Method + Headers + Body，再用字段路径取 remaining/total/used，配 `scale` 倍率 | 原型 server.py `p_custom`，等价移植 |

**明确列入二期（一期不实现）：** 阿里云百炼（`GET /modelstudio/billing/overview` 只能查账单做近似）、小米 MiMo、商汤 SenseNova —— 这三家都没有公开的余额接口。

## 三、需求池（P0 / P1 / P2）

> **P0 = 必须有，一期全做**；**P1 = 应该有，一期挑少量做**；**P2 = 锦上添花或二期**。
> 一期范围：**P0 全部 + P1-1（阈值告警）**。

### 3.1 P0 需求（一期必做，共 12 条）

| # | 需求 | 验收标准 | 继承来源 |
|---|---|---|---|
| P0-1 | **账号增删改**：界面表单添加/编辑/删除账号，字段含显示名、平台类型、密钥或令牌、启用开关 | 全程不碰配置文件即可加一个 DeepSeek 号并看到余额 | 原型的 accounts.json，改为界面驱动 |
| P0-2 | **启用/停用开关**：单个账号可临时关掉，不再查询、不占卡片位 | 关掉的账号不出现在面板，也不参与汇总 | `enabled` 字段 |
| P0-3 | **一屏卡片网格展示** | 响应式网格，每张卡片显示：账号名、平台标签、剩余（大号字）、总额、已用、单位、进度条、最后更新时间 | 原型 index.html 卡片 |
| P0-4 | **手动刷新**：顶部"刷新"按钮刷新全部；单卡片刷新按钮只刷这一个 | 点击后 3 秒内看到新数据；刷新中按钮禁用防连点 | 原型的 force=1 |
| P0-5 | **定时自动刷新，间隔可配置**（设置里选 1/5/15/30/60 分钟） | 到点自动刷，状态行显示"每 X 分钟自动刷新"；**窗口隐藏时暂停刷新**，回到前台立刻补一次 | 原型 60 秒轮询 |
| P0-6 | **4 个内置适配器**：deepseek / siliconflow / newapi / custom | 4 类账号都能正确取数；适配器注册表结构一致，加新平台只需加一个文件 + 注册一行 | 原型 `PROVIDERS` 字典 |
| P0-7 | **密钥安全存储**：Electron `safeStorage` 加密后落盘；界面只显示掩码 `sk-****1234`，不回显明文（编辑框留空表示不修改） | 用记事本打开配置文件看到的是密文；截图分享不会泄露密钥 | 新增（原型是明文） |
| P0-8 | **配置持久化到本地文件**（用户数据目录下的 `config.json` + `snapshots.json`），程序重启后配置仍在 | 关掉重开，账号和设置都还在；配置文件损坏时有兜底提示而不是白屏 | 原型 accounts.json 热加载 |
| P0-9 | **失败卡片明显标红 + 人话提示** | 卡片边框变红、右上角标"失败"、中间写人话原因（见 3.4 错误文案表），不出现英文堆栈 | 原型 `.card.bad` |
| P0-10 | **顶部汇总条**：账号总数 / 按单位分别合计剩余 / 查询失败数 | 单位不同的账号分别合计，不混加；有失败时失败数显示红色 | 原型 summary 区 |
| P0-11 | **查询并发与容错**：多账号并发查询（上限 8）、单账号超时 15 秒、60 秒内重复请求走缓存；一个账号失败不影响其它 | 8 个账号全量刷新总耗时 < 单个最慢账号耗时 + 2 秒 | 原型 ThreadPoolExecutor + 缓存 |
| P0-12 | **浏览器自动化模块占位**（架构预留） | 主进程目录里存在 `browser/` 模块与统一接口定义（含 `launch / login / refreshCookie / close` 空实现与说明注释），**不安装 Playwright / Chromium 依赖，不实现具体功能** | 新增（为二期铺路） |

| # | 需求 | 说明 | 优先级 |
|---|---|---|---|

### 3.3 P2 需求（二期及以后）

| # | 需求 | 说明 |
|---|---|---|
| P2-1 | **浏览器自动化（真实能力）** | 应用自带一个独立 Chromium（Playwright 之类），自动登录网页后台、自动刷新 Cookie、自动抓余额。用于 MiMo / 商汤这类只有网页能看到余额的平台。依赖体积约 150MB，一期不引入 |
| P2-2 | 二期平台适配器 | 阿里云百炼（账单近似）、小米 MiMo（余额 + Token Plan）、商汤 SenseNova |
| P2-3 | Windows 安装包 + 开机自启 + 自动更新 | NSIS 安装包、静默更新 |
| P2-4 | 浅色主题 / 主题切换 | 一期只做深色 |
| P2-5 | 多语言（中/英） | 一期只做中文 |
| P2-6 | 局域网/手机访问 | 需显式开启并二次确认（有安全风险，默认关闭） |

### 3.4 失败原因 → 人话文案对照表（P0-9 依据）

用户看不懂 HTTP 状态码，程序必须翻译成人话：

| 程序内部情况 | 界面显示的人话 |
|---|---|
| HTTP 401 / 403 | 密钥错了或过期了，去平台后台重新生成一个 |
| HTTP 404 | 网址填错了，检查中转站地址（只填域名，不要带 /v1） |
| HTTP 429 | 查太频繁了，平台限流了，把自动刷新间隔调大一点 |
| HTTP 5xx | 平台自己挂了，等一会儿再试 |
| 请求超时 | 连不上平台，检查网络或代理 |
| 证书/网络错误 | 网络不通，检查代理或防火墙 |
| 返回不是 JSON | 平台返回的不是数据（可能是登录页），多半是 Cookie 过期了 |
| 字段路径取不到值 | 没在数据里找到余额字段，检查一下"取值路径"填对没 |
| 缺必填项 | 还有必填项没填：xxx |
| 其他未知错误 | 查询失败（后面跟一行小字原始信息，方便排查） |

## 四、UI 设计稿（文字 + 线框）

### 4.0 视觉基调

- **深色主题**（常驻后台工具，配合深色 IDE）。沿用原型配色：`#16181d` 背景 / `#1e2128` 卡片 / `#333842` 边框 / `#e8eaed` 主文字 / `#9aa0aa` 次要 / `#6b7280` 更弱；成功绿 `#4ade80`、警告黄 `#fbbf24`、失败红 `#f87171`、主题蓝 `#60a5fa`。
- 默认窗口 **1100 × 760**，最小 900 × 600。
- **信息密度高但不拥挤**：卡片内边距 16px，卡片间距 14px，网格列宽 `minmax(300px, 1fr)` 自适应；字号层级克制（余额 26px / 卡名 15px / 辅助 12px / 页脚 11px）。
- 数字自带"万 / 亿"缩写（≥1万显示 `1.23 万`，≥1亿显示 `1.23 亿`），避免长数字撑破卡片。

**卡片内部信息层级（从上到下，优先级递减）：**

1. 第一行：账号名（15px 加粗）+ 平台类型标签（11px 灰边框小胶囊）+ 右上角单卡刷新图标
2. 第二行：**剩余余额**（26px 大号字 + 单位小字）—— 整张卡片的视觉重心
3. 第三行：使用进度条（6px 高，绿→黄→红随用量变化）+ "已用 X / 总额 Y / Z%"
4. 第四行（有才有）：子项明细，如 DeepSeek 的"赠送余额 / 充值余额"、中转站的"用户 / 换算比率"
5. 底部：左边备注（平台返回的说明），右边"X 分钟前"（缓存命中加"· 缓存"）

**失败卡片**：边框和底色偏红，隐藏数字区，居中显示人话原因（14px 红色），底部保留失败时间。

## 五、数据模型

### 5.1 账号对象（Account）

一个账号 = 一个你要监控的平台账户 / 一张卡。

| 字段 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `id` | string(uuid) | 是 | 唯一标识，改名也不会丢历史数据 |
| `name` | string | 是 | 显示名称，如"DeepSeek 主号" |
| `type` | enum | 是 | `deepseek` / `siliconflow` / `newapi` / `custom`（二期加 `mimo` / `bailian` / `sensenova`） |
| `enabled` | boolean | 是 | 默认 true；false 不查询、不展示 |
| `group` | string | 否 | 分组名，P1-7 用 |
| `secret` | string(密文) | 视类型 | **加密存储**的主凭证：deepseek/siliconflow 是 API Key，newapi 是令牌，custom 可不填（凭证放在 headers 里） |
| `base_url` | string | newapi 必填 | 中转站域名，不带 `/v1` |
| `user_id` | string | 否 | newapi 的 `New-API-User` Header 值 |
| `quota_per_usd` | number | 否 | newapi 换算比率，默认 `500000` |
| `quota_total` | number | 否 | 平台不返回总额时手动填（如 DeepSeek） |
| `unit` | string | 否 | 显示单位，`CNY` / `USD` / `元` / `积分`… |
| `request` | object | custom 必填 | `{ url, method, headers{}, body }` |
| `extract` | object | custom 必填 | `{ remaining, total, used, unit, scale, items[] }`，值为点号字段路径 |
| `scale` | number | 否 | 倍率，默认 1 |
| `threshold` | number | 否 | 低余额阈值（P1-1），不填则用全局默认 |
| `notice_enabled` | boolean | 否 | 该账号是否参与提醒，默认 true |
| `last_status` | enum | 否 | 最近一次结果：`ok` / `error` |
| `last_error` | string | 否 | 最近一次失败的人话原因 |
| `last_ts` | number | 否 | 最近一次成功查询的时间戳（毫秒） |
| `created_at` / `updated_at` | number | 是 | 创建 / 更新时间 |

### 5.2 余额快照（Snapshot）

每次查询成功（或失败）留一条，供 P1-2 画趋势图。

| 字段 | 类型 | 说明 |
|---|---|---|
| `id` | string(uuid) | 主键 |
| `account_id` | string | 关联 Account.id |
| `ts` | number | 查询时间（毫秒时间戳） |
| `ok` | boolean | 是否成功 |
| `remaining` | number \| null | 剩余 |
| `total` | number \| null | 总额 |
| `used` | number \| null | 已用 |
| `unit` | string | 单位 |
| `note` | string | 备注 / 失败原因 |
| `items` | array | 子项明细 `[{ planName, remaining, total, used, unit }]` |
| `latency_ms` | number | 耗时，用于排查慢平台 |
| `source` | enum | `live` 实时 / `cache` 缓存 |

> 一期**只写不画**（落盘快照但不做图表页）；可设置保留天数（默认 30 天），超期自动清理，防止文件无限变大。

## 六、待确认问题（需用户拍板）

| # | 问题 | 我的建议 | 为什么需要拍板 |
|---|---|---|---|
| **Q1** | **自动刷新默认间隔**设多少？ | 5 分钟 | 原型是 60 秒，但常驻后台太频繁会触发平台限流（429）。余额不是股票，5 分钟足够。可选项：1 / 5 / 15 / 30 / 60 分钟 |
| **Q2** | **低余额阈值默认值**设多少？按什么单位？ | 官方平台 ¥20，中转站 $2 | 各家单位不同（元/美元/积分/点数），默认值要不要按平台类型分别设？还是统一一个数字让用户自己改？ |
| **Q3** | **中转站 quota 换算比率**怎么定？ | 默认 `1 美元 = 500000` 点（沿用原型），界面上可改 | 每个站点比率可能不一样（有的 1:500000，有的 1:1000000）。是让用户第一次添加时手动试，还是我们做一个"帮我算"的引导（填一次已知金额反推）？ |
| **Q4** | **需不需要账号分组？** | 一期不做，二期做 | 如果你打算监控 20+ 个账号（比如好几个中转站实例），分组很必要；如果就 5-8 个，一屏能看完，可以省掉。请告知你预计会配多少个账号 |
| **Q5** | **是否需要"合计折算成人民币"？** | 一期只按单位分别合计，不做汇率折算 | 汇率从哪来（写死 / 联网取 / 手填）？写死会不准，联网取多一个外部依赖，违背"不联网上报"的原则 |
| Q6（补充） | **一期要不要做系统托盘？** | 一期不做（点 × 直接退出） | 常驻托盘更符合这类工具的定位，但会带来"后台进程关不掉"的困惑。你更想要哪种？ |

## 七、非功能要求（一期）

| 项 | 要求 |
|---|---|
| 安全 | 所有请求直连用户在配置里填的平台地址；程序自身不向任何第三方上报；密钥 `safeStorage` 加密；主进程与渲染进程隔离，渲染进程拿不到密钥明文 |
| 性能 | 8 个账号全量刷新 < 最慢单账号耗时 + 2 秒；界面刷新不掉帧 |
| 稳定 | 单账号失败不影响其它；配置文件损坏时给出"配置坏了，是否恢复上一次备份"的提示，不白屏 |
| 体积 | 一期**不引入 Playwright / Chromium**（约 150MB），只保留占位模块 |
| 平台 | 一期只保证 Windows 11 可用（macOS 顺带能跑即可，不做适配） |
| 可维护性 | 加一个新平台 = 加一个适配器文件 + 注册表一行，不改其它代码 |
